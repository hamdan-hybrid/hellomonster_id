# Multi-bahasa (i18n) DOMPET USAHA

Empat bahasa antarmuka: **Indonesia** (`id`, bawaan & cadangan), **English** (`en`), **Hokkien** (`nan`),
**Korea (한국어)** (`ko`).
Bahasa hanya mengubah tampilan. Data transaksi, nominal, kode status, nilai API, dan hak akses tidak berubah.
Tema terang/gelap: lihat bagian [Tema tampilan](#tema-tampilan-terang--gelap) di akhir.

## Ringkasan arsitektur

| Bagian | File | Fungsi |
|---|---|---|
| Kamus antarmuka | `public/js/locale-id.js`, `locale-en.js`, `locale-nan.js`, `locale-ko.js` | JSON murni dibungkus `export default …;`. Struktur kunci sama di keempat file. |
| Mesin terjemahan | `public/js/i18n.js` | `t(kunci, param)`, `tx()` (parameter berupa elemen DOM), bentuk jamak English (`kunci_one`), format tanggal, waktu relatif, angka ringkas, `setLanguage()`, event `languagechange`. |
| Tombol bahasa | `public/js/i18n-ui.js` | Tombol + menu (ARIA `menu`/`menuitemradio`, keyboard ↑ ↓ Home End Esc, sentuh). `langNotice()` untuk halaman tanpa toast. |
| Server | `src/i18n/index.js` | Validasi kode bahasa, `<html lang data-lang>` yang benar saat halaman dikirim, terjemahan pesan galat API. |
| Katalog pesan server | `src/i18n/messages.en.json`, `messages.nan.json`, `messages.ko.json` | Kunci = teks Indonesia asli (pola gettext, `{param}` untuk bagian berubah). |
| Preferensi akun | migrasi `019_user_language.sql`, `021_user_language_ko.sql` | Kolom `users.language` (`id`/`en`/`nan`/`ko`/NULL, CHECK constraint). |
| Font PDF Hokkien & Korea | `public/fonts/du-pdf-han-*.ttf`, `du-pdf-ko-*.ttf`, `scripts/pdf-font/` | Latin Noto Sans + Han Droid Sans Fallback / Hangul Noto Sans CJK KR, hanya karakter kamus. |
| Test | `test/i18n.test.js`, `test/theme.test.js` | Validasi kamus, katalog, API, persistensi, PDF; skrip tema & token warna gelap. |

Tanpa library tambahan: aplikasi memakai Node.js/Express + modul ES biasa tanpa build step, jadi sistem
terjemahan dibuat sendiri (±250 baris) alih-alih memasang i18next.

### Alur bahasa

1. **Halaman setelah login** (`/backoffice`, `/pos`): server membaca `users.language` dari sesi dan mengirim
   `<html lang="en" data-lang="en" class="i18n-wait">` + `modulepreload` kamus English. Akun tanpa pilihan → Indonesia.
2. **Halaman sebelum login** (`/login`, `/pos/login`, `/pos/setup`): memakai cookie perangkat `du_lang`
   (bukan rahasia, `SameSite=Lax`, `Secure` di HTTPS). Nilai di luar `id|en|nan|ko` diabaikan.
3. `initI18n()` memuat kamus bahasa aktif (Indonesia selalu dimuat sebagai cadangan), menerjemahkan teks statis
   `[data-i18n]` / `[data-i18n-attr]`, lalu menampilkan halaman. Tidak ada kilatan teks bahasa lain.
4. **Ganti bahasa** lewat tombol: kamus diunduh (sekali, lalu di-cache), halaman dirender ulang tanpa reload,
   pilihan disimpan ke akun (`PUT /api/auth/me/language` atau `PUT /api/pos/auth/me/language`, wajib CSRF,
   divalidasi terhadap `LANGUAGES` di `src/i18n/index.js`) dan ke cookie perangkat.
5. Di layar login, bahasa yang **dipilih di layar itu** dikirim bersama login (`language`) dan disimpan ke akun.
   Bahasa perangkat yang tidak dipilih di layar itu tidak dikirim, supaya pilihan pengguna lain di perangkat
   yang sama tidak menimpa preferensi akun.
6. Setiap permintaan API mengirim header `X-Lang`. Error handler menerjemahkan `error.message`;
   `error.code` dan status HTTP tidak berubah.

### POS

Ganti bahasa di layar kasir merender ulang layar dengan **keranjang, voucher, metode bayar, kategori, dan
halaman katalog yang sama** (tanpa memuat ulang data). Selama dialog terbuka, bar atas tidak bisa diklik,
jadi pergantian selalu terjadi di layar kasir.

## Bahasa Korea

- Bahasa Korea standar (표준어) dengan Hangul, gaya sopan formal (합니다/하세요) yang lazim di aplikasi kasir
  dan perangkat lunak bisnis Korea. Kode `ko`, atribut HTML `lang="ko"`. Label tombol bendera Korea Selatan + `한국어` (seperti Hokkien `闽南语`), di menu `Korea (한국어)`.
- Istilah bisnis konsisten: 상품 (produk), 지점 (cabang), 캐셔 (kasir), 단말기 (terminal), 근무 (shift),
  재고 (stok), 재고 실사 (opname), 매입 (pembelian), 지출 (pengeluaran), 매출원가 (HPP), 쿠폰 (voucher),
  영수증 (struk), 반품 (retur), 환불 (refund).
- Teks Korea memakai `word-break: keep-all` (baris tidak memotong di tengah kata) dan urutan font
  Plus Jakarta Sans → Apple SD Gothic Neo / Malgun Gothic / Noto Sans KR (`base.css`, `html[lang='ko']`).

## Format tanggal, angka, mata uang

- Tanggal: `Intl.DateTimeFormat` (`id-ID`, `en-US`, `ko-KR` → `2026년 10월 23일 금요일`), jam 24 jam.
  Hokkien: ICU belum punya data `nan`, jadi tanggal disusun dengan pola aksara Han (`2026年10月22日 禮拜四`)
  dari kamus Hokkien.
- Angka & Rupiah memakai konvensi Indonesia di semua bahasa (`Rp 1.500.000`), karena transaksi dalam Rupiah
  dan input nominal memakai format ini. Nilainya tidak berubah, hanya tampilan.
- Angka ringkas: `2,5 jt` / `2,5 M` (id), `2,5 M` / `2,5 B` (en), `250 萬` / `2,5 億` (nan), `250 만` / `2,5 억` (ko).
- Bentuk jamak English: `kunci_one` + `kunci` (`1 transaction` / `3 transactions`), parameter harus `{count}`.

## Yang sengaja tidak diterjemahkan

- **Struk belanja, struk retur, slip tutup shift** (dicetak printer/dibagikan): tetap bahasa Indonesia karena dokumen
  untuk pelanggan/toko, bukan antarmuka kasir. Bisa dijadikan pengaturan "bahasa struk" bila diperlukan.
- **Data usaha**: nama produk, kategori, pemasok, cabang, terminal, catatan, alasan yang diketik pengguna.
  Nama metode bayar bawaan (Tunai, Transfer, Kartu) diterjemahkan selama belum diubah pemilik.
- **Kode teknis**: kode izin (`users.manage`), kode galat API, nomor dokumen, SKU.
- Pesan galat server yang belum ada di katalog tampil dalam bahasa Indonesia (bukan kosong).

## PDF berbahasa Hokkien & Korea

Font standar PDF (Helvetica) tidak punya aksara Han maupun Hangul. `bo-pdf.mjs` (`PDF_FONT_FILES`) memuat
`/fonts/du-pdf-han-{normal,bold}.ttf` (Hokkien, ±135 KB) atau `/fonts/du-pdf-ko-{normal,bold}.ttf` (Korea, ±75 KB)
hanya saat ekspor, lalu menanamnya. Isinya hanya karakter kamus bahasa itu + Latin-1; aksara lain (mis. nama
produk berbahasa Mandarin/Korea yang tidak ada di kamus) tidak tercetak. Setelah menambah atau mengubah
terjemahan Hokkien atau Korea, buat ulang font (Korea butuh paket `fonts-noto-cjk`, atau `NOTO_CJK_DIR`):

```sh
python3 -m venv /tmp/fontenv && /tmp/fontenv/bin/pip install fonttools
/tmp/fontenv/bin/python scripts/pdf-font/build.py
```

`test/i18n.test.js` gagal bila ada karakter kamus yang belum ada di font. Lisensi: `public/fonts/du-pdf-han-LICENSE.txt`
(Noto Sans: SIL OFL 1.1; Droid Sans Fallback: Apache-2.0) dan `du-pdf-ko-LICENSE.txt` (Noto Sans & Noto Sans CJK:
SIL OFL 1.1).

## Menambah atau mengubah teks

1. Tulis teks lewat `t('namespace.kunci', { param })` — jangan teks tetap di modul. Label di tingkat modul
   (konstanta) dibuat fungsi agar dievaluasi saat render, mis. `const TABS = () => [...]`.
2. Tambahkan kunci yang sama ke **keempat** kamus (parameter `{nama}` harus sama). Kunci belum diterjemahkan
   akan memakai teks Indonesia, kunci yang tidak ada sama sekali tampil sebagai nama kuncinya + peringatan konsol.
3. Teks HTML statis: `<span data-i18n="kunci">`, atribut: `data-i18n-attr="placeholder:kunci;aria-label:kunci2"`.
4. Pesan galat server baru: tambahkan ke `src/i18n/messages.en.json`, `messages.nan.json` & `messages.ko.json`
   (kunci = teks Indonesia persis; bagian berubah ditulis `{nama}`).
5. Jalankan `npm test` (`test/i18n.test.js` memeriksa struktur kunci, JSON, duplikat, teks kosong, parameter,
   kunci yang dipakai kode, katalog server, dan font PDF).
6. Jangan beri nama variabel lokal `t`/`tx` di modul yang memakai `t()` — akan menutupi fungsi terjemahan.

## Keamanan

- Kode bahasa divalidasi di server (endpoint, login, header `X-Lang`, cookie) dan di database (CHECK constraint).
- Cookie `du_lang` hanya berisi `id|en|nan|ko`; nilai lain diabaikan, tidak pernah ditulis mentah ke HTML.
- Endpoint preferensi bahasa memakai autentikasi & CSRF yang sama dengan endpoint akun lain.
- Kamus tidak berisi rahasia; semua teks dirender dengan `textContent`.

## Tema tampilan (terang / gelap)

Tombol bulan/matahari (ikon Lucide) tepat di kanan tombol bahasa di semua halaman: Backoffice, POS kasir,
login POS, pemasangan terminal, dan login Backoffice. Berganti tema tanpa memuat ulang halaman.

| Bagian | File | Fungsi |
|---|---|---|
| Tema sebelum tampil | `public/js/theme-boot.js` | Skrip biasa di `<head>` sebelum CSS: memasang `<html data-theme>` dari pilihan tersimpan, atau tema perangkat (`prefers-color-scheme`) bila belum pernah memilih. Tidak ada kilatan terang→gelap. |
| Tombol & penyimpanan | `public/js/theme.js` | `themeToggle()`, `setTheme()`, event `themechange`; ikut berganti bila tab lain/tema perangkat berubah. |
| Warna | `public/css/base.css` | Semua warna lewat token (`--surface`, `--ink`, `--line`, `--navy-*`, `--brand-*`, `--chart-*`, …). `:root[data-theme='dark']` mengganti nilainya. |

- Pilihan disimpan **per perangkat** (localStorage + cookie `du_theme`, berlaku 1 tahun), bukan di akun, jadi
  tidak perlu perubahan database; kasir yang bergantian di satu terminal melihat tema yang sama.
- **Tetap terang di mode gelap** (`.receipt`, `.receipt-preview`): pratinjau struk mengikuti kertas cetak.
  PDF & struk cetak tidak terpengaruh tema. Panel visual halaman login tetap biru tua bermerek; kartu
  ilustrasinya ikut gelap.
- Isian otomatis browser (username/password tersimpan) memakai warna kolom aplikasi di kedua tema
  (`.input:-webkit-autofill`, `.input:autofill` di `base.css`).
- Logo: `img.logo-light` / `img.logo-dark` (`public/img/logo-dark.png`) ditukar otomatis.
- Warna baru: pakai token, jangan heksa tetap. `test/theme.test.js` memastikan setiap token warna terang punya
  nilai gelap dan setiap halaman memuat `theme-boot.js` sebelum stylesheet.
